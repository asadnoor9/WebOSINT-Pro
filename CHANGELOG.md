# Changelog

All notable changes to this project are documented here.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [2.0.0] - 2026-08-04

### Changed
- **Reporting is now a single package.** `reports/` and `reporting/` have been
  merged into `reporting/`, which previously contained only three-line shims
  re-exporting from `reports/`. Writers are now `reporting/{base,json,html,
  markdown,csv,pdf,docx,export}.py`, every writer subclasses
  `reporting.base.BaseReport`, and `reporting.export` owns format selection.
- **All runtime artifacts live under `output/`.** Reports, logs and caches are
  written to `output/reports/`, `output/logs/` and `output/cache/`, resolved by
  the new `core.paths` module and relocatable with `WEBOSINT_OUTPUT_DIR`.
  Nothing generated by a scan is written to the repository root any more.
- **Report writing is centralised.** The controller no longer imports writers by
  string name; directory creation and `0600` permissions are applied once in
  `BaseReport.write()` instead of being repeated per format.
- `config.json` is now shipped as `config.example.json` and the real file is
  git-ignored, so local values and keys cannot be committed.
- Packaging metadata completed: license, authors, keywords, classifiers, project
  URLs, per-feature extras, and coverage, mypy and stricter Ruff configuration.
- `.gitignore` rewritten to cover generated output, local config, runtime state,
  build artifacts, caches, editor files and OS noise.

### Fixed
- **CI is green again.** `tests/test_safety.py` and `tests/test_json_report.py`
  asserted against constructor keywords (`open_target`, `scope_file`, `redact`)
  that were removed releases ago, failing 11 tests on every push. They are
  replaced by `tests/test_reporting_formats.py`, which covers the merged
  reporting package against its real API.
- Ruff is pinned in CI, so a new Ruff release can no longer turn a green
  pipeline red without a reviewable version bump.
- README badges point at `asadnoor9/WebOSINT-Pro` instead of a placeholder, so
  the CI badge renders instead of showing a broken image.

### Added
- `core/paths.py`: one authority for every runtime path.
- `reporting/base.py`: shared writer contract with deterministic, filesystem-safe
  report naming.
- `reporting/export.py`: declarative format registry with lazy imports, so a
  missing optional dependency costs one format rather than the whole report set.
- CI jobs for packaging build, distribution metadata validation, console-script
  smoke test, and committed-artifact and local-config hygiene.
- CodeQL workflow (per-PR and weekly) and a tag-driven release workflow that
  verifies the tag matches the project version and the changelog.
- `.github/CODEOWNERS` requiring review on safety-critical and supply-chain code.

### Removed
- The `reports/` package (merged into `reporting/`).
- The `reporting/*_report.py` shim modules.
- `docs/ARCHITECTURE_ROADMAP.md`, superseded by `ARCHITECTURE.md` and describing
  a structure and Docker support that no longer exist.
- Remaining Docker references from the installation guide; Docker is not a
  supported deployment path.


### Added (engine, reporting and service)
- **Engine 3.0**: staged pipeline, plugin lifecycle, event bus and shared cache.
  Modules no longer call each other directly.
- **Technology-aware scanning**: fingerprints the target first and skips module
  families that cannot apply, which is the single largest speed win.
- **Confidence engine**: findings are scored and only reported above the
  reporting threshold, with the supporting evidence attached.
- **Report engine**: JSON, Markdown, HTML, CSV, PDF, Word and Excel output, with
  executive, technical, SOC, developer and risk-dashboard audiences.
- **Web dashboard** with background scans, live progress, adjustable scan speed,
  verbosity control, and in-portal report viewing and download.
- **Service management**: `webosint start|stop|restart|status|health|doctor`,
  plus systemd installation and start-on-boot support.
- **Host and infrastructure reporting**: operating system, network, ISP, exposed
  port versions, services and web-hosting stack.
- Scan history and inventory persistence.

### Fixed (scan accuracy)
- Email authentication results are now evaluated against the organisational
  domain, so SPF, DKIM and DMARC are no longer reported as missing on subdomains
  that legitimately inherit them.
- Next.js sites are fingerprinted correctly and no longer trigger WordPress,
  PHP or database probes.
- LAN access: the service unit no longer fails with a read-only runtime
  directory, and remote binding works as documented.
- Risk summary tables populate instead of rendering empty.

### Security
- Authorization gate, allowlist enforcement, private and reserved address
  blocking, SSRF-safe redirect handling, passive-by-default operation and
  TLS verification on by default.
- Redaction across every output path, configurable detail levels, no raw HTTP
  persistence, retention and cleanup, telemetry off by default.
- The web dashboard ships with authentication disabled by design; it is intended
  to be bound to localhost or protected at the network layer.
